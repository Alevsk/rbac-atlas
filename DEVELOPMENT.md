# Development Guide

## Prerequisites

- [uv](https://docs.astral.sh/uv/) (Python package manager)
- [Hugo](https://gohugo.io/installation/) (extended edition)
- Node.js 18 or later and npm
- Make
- Helm and [rbac-scope](https://github.com/alevsk/rbac-scope) (only to run the data pipeline)
- [Trivy](https://trivy.dev/) and [crane](https://github.com/google/go-containerregistry/tree/main/cmd/crane)
  (only to run the image vulnerability scan, see [docs/image-vulns.md](docs/image-vulns.md))
- Docker (optional)

## Python Environment Setup

1. Install uv:

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   ```

2. Install dependencies:

   ```bash
   uv sync
   ```

   Or install everything (npm, Playwright, uv) using make:

   ```bash
   make install
   ```

Run `make` with no arguments to list all targets.

## Development Workflow

1. Run the data pipeline to generate new findings (pulls charts, analyzes them, regenerates pages and the report):

   ```bash
   make update
   ```

2. Build static site:

   ```bash
   make build      # Development build
   make build-prod # Production build
   ```

   A full build renders ~28k pages and needs a lot of memory and time.

3. Start development server:

   ```bash
   make serve      # All pages
   make serve-dev  # Only pages and rules (fast)
   ```

4. Run tests and linters:

   ```bash
   make test-python # Python unit tests
   make test        # Playwright tests, against a running `make serve`
   make lint        # Markdown and template checks
   ```

## Docker

The `Dockerfile` builds the full site and serves it with an unprivileged nginx on port 8080.
CI does not build or publish this image; the site is deployed to GitHub Pages. The image is
for local use, and its `toolchain` stage is the dev container image
(`devcontainer/.devcontainer.json`).

```bash
make docker        # Build the image (full site build, needs a lot of memory)
docker run -it --rm --name rbac-atlas -p 8080:8080 rbac-atlas:latest
```

## Project Structure

- `projects.yaml`: Helm charts and OCI artifacts that are tracked
- `content/`: Hugo content files (chart pages are generated by `json2hugo.py`)
- `layouts/`, `assets/`, `static/`, `themes/`: Hugo templates and assets
- `data/`: Hugo data (time series and image vulnerability data)
- `manifests/`: Generated RBAC manifests (rbac-scope output)
- `reports/`, `report/`: Daily report snapshots and the scripts that produce them
- `vulnscan/`: Image vulnerability pipeline
- `scripts/`: Data pipeline helper scripts
- `tests/`: Python unit tests and Playwright tests
